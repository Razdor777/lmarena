# Аудит перед апдейтом на 1.26.62 (26.62)

Дата: 2026-11-06. Проверено по репозиторию `Razdor777/lmarena`, ветка `arena/b26c371c-lmarena`,
коммит `0e98be7`.

Коротко: **тебе не надо мне ничего показывать — я прочитал весь проект сам.** Ниже что
где лежит, что реально сломано и какие есть варианты апдейта.

---

## 1. Что лежит в репозитории

| Дерево | Что это | Размер |
|---|---|---|
| корень (`src/`, `include/`, `resources/`) | **Solstice под 1.21.44** — твой рабочий клиент, ~140 000 строк, 198 модулей, 30 команд | ~26 МБ |
| `26.62/` | вторая база — **обрезанный форк Dexko** (та же Solstice, но порезанная), ~58 000 строк, 129 модулей, 20 команд | ~37 МБ |
| `dexko/` | только README + ~40 файлов-огрызков | 320 КБ |

В корне 11 файлов с конфликт-маркерами (`<<<<<<< HEAD`), 82 блока. В `26.62/` —
13 файлов, 34 блока (маркеры там **другого формата**: `<<<<<<<<` с 8 знаками и
подписями `HEAD:26.62/src/Solstice.cpp` / `...:26.62/src/Dexko.cpp`).

Проект **сейчас не собирается ни в одном из трёх деревьев**: маркеры конфликтов в
`.cpp`, `.hpp` и в `CMakeLists.txt` — это синтаксическая ошибка.

---

## 2. Главное: `26.62/` — это не «Solstice 1.21.44 + мелкие правки»

Это база **Dexko** — из неё удалено всё, что не компилировалось в лёгкую сборку.
Твой код при переносе резался, а не «ошёл»:

- **75 модулей** из `src/` отсутствуют в `26.62/src/` (Aimbot, GhostMode, LastTP,
  OreMinerV2, SchematicBuilder, CustomCrosshair, HitParticles, ArmorHUD, Nametags и т.д.).
- **10 команд** отсутствуют (SBuild/SPaste/SCopy/Pos1/Pos2, Spammer, FakeChat, PlayerOffset…).
- **14 утилит** вырезано: `ItemTextures`, `ItemAtlas`, `ClientPack`, `CubemapGenerator`,
  `PngWriter`, `HealthTracker`, `CPSTracker`, `PlatformTracker`, `NurikIcons` и др.
  При этом **31 файл** твоего кода их включает → при переносе модулей это первое, что отвалится.
- **4 события и 4 хука** вырезано: `EntityHurtEvent`, `HurtColorEvent`,
  `ProjectileHitEvent`, `ContainerSlotHoveredEvent`, `HealthHooks`, `ProjectileHooks`,
  `HurtColorHook`, `AmbienceHook`.
- Добавлено в 26.62 то, чего у тебя нет: `IRC` (клиент + команда + модуль), `AutoWalk`,
  `AutoEat`, `ScriptingGui` (+ `include/Luau`), `LevelRendererHook`,
  `SetupShaderParameterHook`, `WndProcHook`, `GrabMouseHook`, `NetherNetHooks`.
- `Authorization` в 26.62 **закомментирован** (у тебя — обязательная проверка
  `dllserver.solstice.works` + `__fastfail`).
- Внутри 26.62 одновременно живут **две системы имён**: часть кода зовёт `Dexko::`
  (8 файлов), часть — `Solstice::` (11 файлов), и оба класса объявлены в
  `Dexko.hpp`/`Solstice.hpp`. Это тоже не соберётся.

Вывод: 26.62 — это **минимальная база под новую версию**, а твои 75 модулей — отдельный
пласт, который в неё нужно вернуть.

## 3. Насколько API разъехался (что будет ломаться при переносе)

При переносе старого кода нужно править:

| Что | Масштаб |
|---|---|
| `MoveInputComponent` переписан полностью (битфилды `MoveInputState` вместо `mIsJumping/mForward/...`) | **23 файла**, 138 обращений |
| `Setting`: `mHideOnClickGUI` → `mHideInMenu` | 1 файл |
| `Module`: убраны `serializeCustomData` / `hasCustomData` (есть в 26.62? частично — проверить при сборке) | 9 + 6 файлов |
| `ClientInstance::getKeyboardSettings()` теперь `KeyboardRemappingLayout*` (было `KeyboardMouseSettings*`) | GhostMode + др. |
| SDK-структуры: `Actor::filler` 0x408 → 0x3d0, монолитный `EntityContext` (373 → 437 строк), `ItemStack`, `Item`, `SerializedSkin` и т.д. | весь SDK |
| `ItemRenderer` в 26.62 — без твоего `ItemRenderer.hpp` (сигнатуры `renderGuiItemNew/iconBlit/...)` | `ItemStack.cpp`, `InventoryHUD` |

Хорошая новость: **209 файлов** в двух деревьях **идентичны байт-в-байт** (команды,
конфиги, часть событий, часть модулей). То есть база не «другая», а именно та же —
обрезанная.

## 4. Версионно-зависимое: где сейчас на самом деле 1.21.44

Это ключевой пункт для «обновить до 26.62»:

| Файл | Корень (1.21.44) | 26.62/ |
|---|---|---|
| `SigManager.hpp` | 128 сигнатур | 94 сигнатуры, 70 общих, 58 корневых отсутствуют |
| `OffsetProvider.hpp` | 98 записей | 123 записи, 65 общих, 58 новых |
| `ComponentHashes.hpp` | **Last updated: 1.21.44** | **Last updated: 1.21.44** (не тронут!) |
| `PacketID.hpp` | 203 записи | 203 записи |

В комментариях 26.62 фигурируют **1.26.51 / 26.51 / 1.21.131** — то есть база снималась
по `1.21.13x` и, судя по всему, частично по beta `1.26.51`. Прямых отметок «1.26.62» в
коде нет. `ComponentHashes` в обеих базах от 1.21.44 — для 1.26 это почти наверняка
неверно (симптом: ESP/аура/скорость не находят актёров и компоненты).

Что это значит: **перенос кода — это половина работы.** Вторая половина —
снять/проверить 94 сигнатуры + 123 оффсета + хэши компонентов + ID блоков/пакетов
на реальном `Minecraft.Windows.exe` 1.26.62. Без бинарника и запуска это не делается —
сейчас у меня в песочнице Linux и нет ни игры, ни MSVC, ни `.exe`.

## 5. Что реально можно сделать прямо сейчас (без exe)

1. **Починить обе базы под сборку**: снять все 116 конфликт-маркеров (34 + 82),
   выбрать единое имя класса (`Solstice` или `Dexko`), починить `CMakeLists.txt`
   (в 26.62 сейчас перемешаны target'ы `Solstice`/`Dexko`, `UNITY_BUILD TRUE/FALSE`,
   линковка DirectXTK vs без него) → получится **собираемый** проект. Это
   проверяемо хотя бы по структуре, и это снимает 100% текущих ошибок компиляции,
   не связанных с версией игры.
2. **Портировать API** (п.3) для 75 модулей + 10 команд + 14 утилит: механическая
   работа по списку — я могу пройти её целиком, файл за файлом.
3. **Собрать «план сигнатур»**: список 58 корневых сигнатур и 33 корневых оффсетов,
   которых нет в 26.62, с указанием, какие модули от них зависят (уже посчитано:
   реальных потребителей мало — `CustomCrosshair`, `ItemUseDelayFix`, `HitColor`,
   `Freelook/Freecam/SpectatorDetector`, `ItemStack`, `ItemRenderer`-зависимые HUD'ы).
   Остальные 40+ — «висят» в SigManager и нигде не используются, их можно просто
   выкинуть, а не переносить.
4. **Подготовить инструменты снятия подписей**: скрипт-выгрузка всех сигнатур в
   единый формат + чекер «сколько раз паттерн находится» (у тебя в docs это
   описано, но нет автоматики).

## 7. Три возможных плана (выбери)

**A. Lite (рекомендую, если нужен результат быстро)**
`26.62/` = база Dexko (новая версия) + переносим только рабочие модули из твоего
списка (сначала Combat/Visual/Movement, без экзотики вроде `SchematicBuilder`,
`Regen`, `OreMinerV2`, `RegionFill`). Убираем дубли имён и маркеры, правим API,
собираем, дальше по логу добиваем сигнатуры. Размер `.dll` меньше, поверхность
поломок — тоже.

**B. Полный порт**
`26.62/` получает **все 75 модулей** + 10 команд + 14 утилит + 4 события + 4 хука.
Дольше и рискованнее (SchematicBuilder/OreMinerV2/Regen тянут за собой много SDK),
но в итоге получаешь полный клиент на новой версии.

**C. Обновить корневой Solstice (1.21.44 → 1.26.62)**
Оставить одну базу (корень), влить в неё новый SDK из `26.62/`, снять маркеры,
переписать сигнатуры/оффсеты. Плюс: ничего не теряется. Минус: самый большой объём
правок в SDK, и весь `dexko`-опыт (IRC/Luau/ScriptingGui) придётся переносить вручную.
