# PDB и символы: что это даёт проекту и как этим пользоваться

Коротко: **PDB — это самый быстрый способ узнать настоящие имена функций и настоящую раскладку
структур для конкретной сборки Minecraft.** Всё, что сейчас в репозитории угадано
(`src/SDK/IDA_Analysis.hpp`, адреса в `AmbienceHook.cpp`, смещения вида `a3 + 120`), при наличии
подходящей PDB заменяется на проверенные данные.

В репозитории для этого лежат два инструмента, не требующие ни IDA, ни Windows:

| файл | что делает |
|---|---|
| `tools/pdb_dump.py` | автономный парсер PDB (MSF/DBI/TPI): имена функций + RVA, глобалы, классы/структуры с размерами и смещениями полей, enum'ы, выгрузка в JSON / список имён для IDA / C++ заголовок |
| `tools/pdb_fetch.py` | читает вшитый в exe идентификатор PDB (RSDS: имя + GUID + Age), сверяет «этот ли PDB к этому exe», ищет подходящую PDB в каталоге и умеет скачать её с сервера символов |

---

## 1. Что именно даёт PDB

* **Имена функций с RVA** — `sub_1442531D0` превращается в `LevelRenderer::renderLevel` (или что
  там на самом деле), а не «большая функция, похожая на рендер».
* **Размеры функций** — важно перед хуком: если функция 12 байт, MinHook её не перепрыгнет.
* **Точная раскладка структур** — размеры и `+offset` каждого поля (`RenderData`, `FogParams`,
  `SkyLight`, `PostProcess`, `IBufferData` и т. д.). Именно то, что сейчас выдумано в
  `IDA_Analysis.hpp` и в `AmbienceHook`.
* **Enum'ы со значениями** — например, реальные значения типов тумана, режимов рендера, пассов.
* **Проверка версии** — GUID+Age из RSDS гарантируют, что PDB именно от этого exe (не «примерно
  та же версия»).

Чего PDB не даёт: она не помогает, если PDB от **другого** билда — там совпадут имена и типы,
но не адреса (см. раздел 4).

## 2. Где брать символы

### 2.1 Клиент 1.21.44 — символов нет (проверено)
У проекта LiteLDev есть публичный пакет символов `bedrock-runtime-data`, и там есть **клиентские**
варианты. Но доступные клиентские теги: `1.21.0.3-client`, `1.21.124-client.*`, `1.21.132-client.*`,
`26.10.4-client.*`, `26.20.4-client.*`, `26.32.2-client.*`, `26.40.5-client.*`, `26.51.1-client.*`.
**Для 1.21.44 клиентских символов нет.** Серверные теги (BDS) есть для 1.21.0.3, 1.21.3.1,
1.21.20.3, 1.21.50.10, 1.21.60.10, 1.21.80+, 1.21.102+, 1.21.120+, 1.21.124+, 1.21.132+ —
но `bedrock_server.exe` это другой бинарник, не `Minecraft.Windows.exe`.

Ссылки:

* релизы символов: `https://github.com/LiteLDev/bedrock-runtime-data/releases`
* сам загрузчик модов (там же в zip лежит `LeviLamina.pdb`): `https://github.com/LiteLDev/LeviLamina/releases`

> Важно: из этой песочницы CDN релизных ассетов GitHub недоступен (виден `api.github.com`, но не
> `objects.githubusercontent.com`), поэтому качать zip'ы нужно тебе, а мне присылать файлы.

### 2.2 Прямой путь: проверить, есть ли PDB у Microsoft
У любого нормального exe внутри есть запись RSDS. Если Microsoft опубликовала символы для этой
сборки — PDB скачается одной командой:

```cmd
python tools\pdb_fetch.py "C:\XboxGames\Minecraft\Content\Minecraft.Windows.exe" --info
python tools\pdb_fetch.py "C:\...\Minecraft.Windows.exe" --download client.pdb
```

Для клиента Minecraft символов обычно нет (404), но это 5 секунд проверки, и `--info` полезен сам
по себе: он даёт GUID+Age, по которым **однозначно** видно, подходит ли какая-нибудь PDB.

### 2.3 Проверка любой PDB на соответствие exe

```cmd
python tools\pdb_fetch.py "Minecraft.Windows.exe" --check скачанная.pdb
python tools\pdb_fetch.py "Minecraft.Windows.exe" --scan C:\symbols
```

`--scan` обходит каталог и печатает, какие PDB совпадают по GUID+Age.

## 3. Как читать PDB

```cmd
:: сводка (имена функций и глобалов с RVA, число типов)
python tools\pdb_dump.py LeviLamina.pdb

:: структуры с размерами и смещениями полей
python tools\pdb_dump.py LeviLamina.pdb --types --filter "Render|Fog|Sky|Actor" --limit 60

:: полный дамп в JSON (это и прислать)
python tools\pdb_dump.py LeviLamina.pdb --json pdb_dump.json

:: список "RVA имя" — импорт имён в IDA (File -> Script / MakeName)
python tools\pdb_dump.py LeviLamina.pdb --names names.txt

:: C++ заголовок со структурами и static_assert'ами на размеры
python tools\pdb_dump.py LeviLamina.pdb --header sdk.hpp --filter "LevelRenderer|RenderData|Fog"
```

Скрипт на чистом Python 3, зависимостей нет, IDA не нужна, читает PDB до нескольких сотен МБ.
Если `--types` пусто, а имена есть — PDB урезана до публичных символов (`pdbcopy -p`): типов в ней
просто нет, это не ошибка парсера.

### Что делать с выводом

* `--names` → в IDA: `File → Script file…` или в командной строке `MakeName(0x1442531D0, "...")`.
  После этого твои дампы читаются глазами, а не по `sub_XXXX`.
* `--header` → в `src/SDK/`, чтобы вместо угаданных смещений были размеры и `static_assert`.
* `--json` → мне: я соберу из него таблицу оффсетов, сигнатуры для `SigManager` и починю
  Ambience/туман/небо на реальные поля.

## 4. Ограничения, которые важно понимать

1. **RVA верны только для той сборки, из которой собрана PDB.** Между 1.21.44 и 1.21.124
   совпадают имена, типы и структура кода, но не адреса.
2. **Серверная PDB ≠ клиентская.** `bedrock_server.exe` и `Minecraft.Windows.exe` — разные
   бинарники: имена/типы переносятся (общий код), адреса — нет.
3. **Перенос между версиями** — это отдельный шаг: сопоставление функций по сигнатурам/строкам
   (binary similarity). Так работает, например, проект `bedrock-mc/lens` (Ghidra + BSim,
   переносит знания из сборок с символами в сборки без них). Для этого нужно, чтобы сначала был
   нормальный экспорт нашей сборки — как раз то, что делает `tools/ida_export.py`.
4. **Юридически/технически**: PDB не коммитим в репозиторий (сотни МБ + лицензия вендора).
   В `.gitignore` уже добавлены `*.pdb`, `*.idb`, `*.i64`, `ida_export.json`.

## 4.5. Перенос клиента на другую версию игры (`tools/sig_migrate.py`)

Доступные клиентские версии, под которые у LeviLamina есть символы (из `docs/.../versions.md`):

| LeviLamina | Версия клиента |
|---|---|
| 1.8.x | **1.21.124.2** |
| 1.9.x | **1.21.132.1** |
| 26.10.x … 26.51.x | 26.10.4, 26.20.4, 26.32.2, 26.40.5, 26.51.1 |

Для 1.21.44 (текущая цель клиента) символов нет ни у кого — ближайшая младшая клиентская сборка
это 1.21.0.3, старшие начинаются с 1.21.124.

Объём работ по переносу (посчитано по репозиторию, `tools/sig_migrate.py --parse`):

```
DEFINE_SIG                87   (байтовые сигнатуры в src/SDK/SigManager.hpp)
DEFINE_INDEX_FIELD        50   (индексы/поля в src/SDK/OffsetProvider.hpp)
DEFINE_INDEX_FIELD_TYPED   8
DEFINE_FIELD              44   (числовые смещения структур — только по типам из PDB)
HARDCODED                  5   (жёсткие адреса в AmbienceHook.cpp)
```

Команды:

```cmd
:: что распознаётся из репозитория
python tools\sig_migrate.py --parse

:: перенос: прогнать все записи по exe целевой версии
python tools\sig_migrate.py --exe "Minecraft.Windows.exe" --names names.txt --md migration.md
```

Отчёт по каждой записи: `OK_UNIQUE` (нашлась ровно одна — адрес в новой версии готов, править
ничего не надо), `MULTIPLE` (несколько совпадений — уточнить), `NOT_FOUND` (код изменился; с
`--names` печатаются кандидаты по именам символов), `MANUAL` (числовые смещения — сверять по типам).

Что проверено без целевого exe: парсер записей прогнан по реальному репозиторию (194 записи,
битых паттернов 0), а сам сценарий — на синтетической паре exe «старая/новая версия»: стабильная
функция находится однозначно, изменённая не находится и получает правильную подсказку по символу,
продублированная даёт два совпадения.

## 5. Практический план

1. Ты: `pdb_fetch.py --info Minecraft.Windows.exe` → покажи вывод (GUID+Age). Заодно `--download`:
   если Microsoft отдаст PDB — задача закрыта на 80%.
2. Ты: скачаешь `bedrock-runtime-data` (любой клиентский тег, ближайший к 1.21.44 — 1.21.124)
   и/или `LeviLamina` (там `LeviLamina.pdb`), и пришлёшь мне либо сам `.pdb`, либо вывод
   `pdb_dump.py --json`.
3. Я: сопоставлю имена/типы с данными из твоего IDB — включая тот самый
   `sub_1442531D0` — и выдам таблицу проверенных оффсетов + сигнатуры, после чего перепишу
   Ambience/туман/небо и `IDA_Analysis.hpp` на реальные имена и поля.
